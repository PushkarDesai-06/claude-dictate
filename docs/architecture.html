claude-dictate architecture

Push-to-talk dictation for Hyprland on Wayland. A real Claude Code CLI runs hidden in its own tmux server with /voice on and acts as the speech-to-text engine. Python code holds Claude's push-to-talk key by injecting keystrokes into tmux, scrapes the transcript off the rendered screen, and types it into whatever window has focus with ydotool.

Components

Hold Super+Space anywhere. Hyprland calls a tiny client, the client talks to a long-running daemon over a unix socket, and the daemon drives Claude Code through tmux. Arrows point in the direction of the call or the data.

Why it is built this way

Each of these came out of probing the real Claude Code TUI and the real desktop. None of it is obvious from the outside.

Raw bytes instead of tmux key names

tmux drops Shift from Ctrl combos, so send-keys C-S-Space reaches Claude as plain ctrl+space. We send the CSI u sequence \e[32;6u as hex with send-keys -H so it arrives intact.

Holding a key means repeating it

A terminal has no key-up event. Claude decides the push-to-talk key is held from auto-repeat, so we resend the sequence every 30ms for as long as we want to record.

Clearing is End + Ctrl+U, in a loop

Ctrl+L redraws the screen but leaves the input alone. Ctrl+U only kills the current visual row, so we send End + Ctrl+U and re-read until the box is empty.

Empty is detected by dim text

An empty box still shows placeholder text after the prompt. The placeholder is drawn dim (SGR 2), so the parser captures with -e and treats a dim run right after ❯ as empty.

Release comes from the keyboard itself

Hyprland release binds fired only 2 out of 6 times in testing. The daemon polls the physical key state from /dev/input with the EVIOCGKEY ioctl every 20ms and keeps the release bind only as a backup.

Typing waits for modifiers

Typing with ydotool while Super was still down produced phantom Super+Space presses and could fire window manager shortcuts. Nothing is typed until every modifier is physically up.

Plan mode with no tools

The session runs claude --permission-mode plan --tools "". If a stray Enter ever submits the input box, Claude can only answer in text; it has nothing to run.

ASCII only on the way out

ydotool presses keys on the current layout, so it cannot type characters outside ASCII. Text is normalized first: accents stripped, curly quotes straightened, fancy dashes made plain.

File map

Entry points
bin/claude-dictate-startStarts the tmux session running Claude Code (120x30, own socket); opens a kitty window unless --detached.
bin/claude-dictatedRuns the daemon (python3 -m claude_dictate.daemon).
bin/claude-dictate-ctlRuns the client that Hyprland calls with press, release or status.
tmux.confExtended keys in CSI u format, zero escape time, no status bar, and a C-S-Space binding that forwards the raw sequence.
~/.config/caelestia/hypr-user.luaOutside the repo: binds SUPER + Space to press, plus a release bind to release.
Daemon and control
claude_dictate/ctl.pyCLI client: sends one command and prints the reply.
claude_dictate/ipc.pySocket path and the line-based send_command protocol.
claude_dictate/daemon.pyMakes sure the session is up, serves the socket, wires the Dictator to YdotoolTyper and PhysicalKeyboard, reports errors with notify-send.
claude_dictate/dictator.pyTurns press and release into one dictation at a time; watches the hotkey, copies nonempty transcripts, waits for modifiers, then types.
claude_dictate/keyboard.pyFinds keyboards in /proc/bus/input/devices and reads which keys are held with EVIOCGKEY, without consuming events.
Claude Code engine
claude_dictate/dictation.pydictate(release): clear, hold push-to-talk, confirm recording, wait for release and final text, clear again.
claude_dictate/transcript.pyFinds the input box between the two rules, detects the placeholder and the level meter, and returns the text.
claude_dictate/session.pyThe only module that calls tmux: send-keys -H, capture-pane -p -e, cursor and pane size.
Output
claude_dictate/clipboard.pyCopies original text with wl-copy, with a bounded timeout and a success result. Clipboard history is maintained by the desktop watcher.
claude_dictate/typers/base.pyTextTyper: the interface for delivering text to the focused app.
claude_dictate/typers/ydotool.pyYdotoolTyper and to_typeable_ascii.
Support
scripts/dictate_once.pyRuns one dictation from a terminal and prints the transcript.
systemd/claude-dictate-session.serviceUser unit that owns the tmux session with Claude Code. Clears any leftover session on start and restarts it if Claude exits.
systemd/claude-dictated.serviceUser unit for the daemon. Wants the session unit, restarts on failure, and is enabled for graphical-session.target. On Hyprland without uwsm it is started from the hyprland.start hook in hypr-user.lua instead.
scripts/install-systemd.shLinks the bin commands into ~/.local/bin, links both units into systemd and enables the daemon.
scripts/probe_dictation.pyHolds push-to-talk for a fixed time and records every distinct pane frame (output in probe-output/).
